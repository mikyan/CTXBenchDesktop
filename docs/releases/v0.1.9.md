## 新增与修复

- **Agent 没启动也有错误诊断**：记录准备任务、配置检查、Git 基线、镜像获取和构建、工作目录权限及 Docker 创建失败。页面显示失败步骤、原始错误摘要、容器启动记录和排查建议，完整异常调用链保存在日志中。
- **保留原始失败原因**：Docker 启动错误不再被后续“缺少 result.json”或结果协议错误覆盖。
- **运行中直接查看输出**：实验、知识库准备任务、运行详情及用例自检等入口支持查看容器标准输出和标准错误，每秒增量刷新。新版 Pi 的依赖安装、执行事件和自定义命令输出不必等结束后才看得到。
- **从头分页查看完整日志**：实时模式显示近期输出；点击“从头查看完整日志”逐页读取所有已保存内容，并可选择更早的执行来源。新日志不再自动丢弃超过 100 万字符的开头，或超过 50 个已结束执行的正文。重试创建独立记录，不覆盖旧错误。
- **只读、安全、易排查**：支持暂停刷新、手动刷新、自动滚动和导出当前窗口。连接中断、采集中断、退出码和旧镜像不支持分别提示。已配置凭据在保存前脱敏，日志不回传给 Agent，不改变任务 Prompt、模型、预算或评分输入。

## 升级与使用

**必须同时更新桌面端和配套应用镜像。**

1. 如果有实验正在执行，先暂停并等待当前阶段结束，再通过软件安全停止评测服务。
2. 安装 v0.1.9 桌面程序，在 **设置 → 应用镜像** 导入本版镜像 ZIP。
3. 保持原 WSL 发行版和数据目录，启动评测服务；服务重启后按需重新填写内存中的模型凭据。
4. 在实验或准备任务中点击 **实时容器日志**；失败记录也提供 **查看完整运行日志** 入口。使用 **从头查看完整日志** 查看错误发生前的全部已保存输出。

历史数据、评测集和评分结果无需删除。旧版本未采集、已经截断或采集失败时丢失的输出不能补回；程序尚未刷出的内容也无法提前显示。部分官方评分器仍将详细单测输出写入证据文件，需要同时查看。

日志归档会持续占用评测服务数据盘，请留意剩余空间。“导出当前窗口日志”只导出当前窗口或当前页，不代表导出整份归档。不要在命令中写入密钥或打印未知、编码变形的凭据。

本版更新自定义命令适配器和项目环境构建实现。若旧的已准备实验提示冻结实现已变化，请保留旧环境完成旧实验，或使用新版重新准备新实验；不要改写历史快照绕过一致性检查。

安装包仍未签名。镜像 ZIP 只包含四个应用镜像，不包含官方评测数据、全部项目镜像或代码仓库。

v0.1.9 adds live stdout/stderr, pre-Agent preparation diagnostics and complete saved-log browsing. Failures show the failing step, original exception chain, container-start evidence and troubleshooting hints. Docker startup failures are no longer replaced by missing Agent-result errors. Read archived output in bounded pages from the beginning, retain earlier attempts, or follow the live tail without changing execution.

Update **both** the Windows installer and matching application-image ZIP, preserving the existing WSL distribution and data directory. Previously missing output cannot be reconstructed. Monitor archive disk usage; exporting visible logs exports only the current window/page. Some official harness details remain in evidence files. Frozen custom-command/project-environment implementation checks still apply: use a matching old environment or prepare a new experiment after upgrading.

Verification includes 817 frontend tests, 285 passing Windows worker tests with 2 platform skips, bilingual browser interactions and 10 isolated real-Docker scenarios. No paid Provider calls were made. The installer remains unsigned; datasets and project images remain separate.
