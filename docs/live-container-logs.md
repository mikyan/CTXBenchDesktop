# 执行诊断与完整运行日志

运行中不用再进入 WSL 手动执行 `docker logs`。当前源码提供只读的容器控制台，每秒增量刷新；需要一起更新桌面端和本地评测服务镜像。默认 Pi 的实时安装输出和 Agent 事件还需要新版 Pi 镜像，旧版镜像无法把内部缓冲的输出提前交出来。

## 从哪里打开

- **实验**：实验行的 **实时容器日志**，包括准备阶段；不必等第一个求解用例出现。
- **知识库**：独立准备任务列表的 **实时容器日志**。
- **运行详情**：上方直接显示当前用例的实时容器日志。评分、约束评审开始后可切换执行阶段。
- **用例自检、导入、安装镜像**：对应任务面板的 **实时容器日志**。

默认优先显示最近失败的诊断；新的尝试启动后自动跟随新执行。用“容器 / 执行阶段”切回之前的准备记录、编码、生成或测试容器。来源很多时，点击“加载更早的日志来源”。每次重试单独保留记录，不覆盖之前的错误。

点击“从头查看完整日志”，使用上一页 / 下一页浏览全部已保存输出，每页最多 6.4 万字符，避免大日志卡住页面。点击“返回实时尾部”继续跟随实时输出。暂停日志刷新、立即刷新、关闭窗口都只影响查看，不会暂停或重跑任务。滚动向上会取消自动滚动；勾选后重新跟随尾部。“导出当前窗口日志”只导出当前窗口或当前页的文本，不代表完整归档。

## Agent 还没启动就失败怎么办

实验列表、准备任务和用例详情会展示失败步骤、原始错误摘要、是否记录到 Agent 容器启动，以及对应排查建议。点击“查看完整执行日志”，可以看到错误前的准备操作与完整异常调用链，包括 Git 基线、工作目录权限、镜像获取、依赖构建和 Docker 创建失败。建议不是自动诊断结论，应结合原始输出检查配置。

准备日志不依赖 Agent 容器存在：在执行准备操作前就建立记录。Git 标准错误、Docker 镜像拉取和构建输出不再仅保留最后几行；Git 的标准输出可能包含代码或评测材料，因此不会复制到诊断记录。Docker 创建失败也不会再被后续“缺少 result.json”覆盖。没有记录到容器启动不等于已经核实没有模型消费；精确用量仍以 Agent 执行记录为准。

## 能看到什么

- Docker 的标准输出和标准错误输出；默认 Pi 的启动安装输出、RPC 事件和错误，以及自定义编码命令输出。
- 自定义用例的测试命令输出、官方评分器主容器的控制台输出。
- 无输出、连接中断后自动重连、日志采集中断、日志结束和实际退出码分别显示。日志采集失败不是功能测试失败；评分仍依据原来的测试结果。
- 旧的评测服务没有此接口时提示更新镜像，不会反复报错或更改正在运行的任务。历史运行没有补录的实时日志，仍可手动选择原有证据文件。

Docker 日志不等于容器里所有文件的内容。部分官方评分器通过子进程执行命令，把详细单测结果写入证据文件；此时控制台可能比较安静，仍需查看评分证据。GitHub/公司 CI 平台的远程执行也不在本地 Docker 控制台内。

如果自己的程序缓冲输出，可以在用例命令中明确使用 `python -u`，或在程序里 `print(..., flush=True)`。还应输出完整的行：不带换行符的进度文本，即使程序已刷新，也可能被 Docker 日志驱动缓冲到之后才显示。工具不会替用户修改 Agent 参数、环境、Prompt 或强制打开调试模式，也不会伪造进度。

## 安全和保留范围

- 容器日志先按本次运行的已配置环境变量和凭据名称脱敏，再写入独立的 `container-logs/logs.sqlite3`。跨多次输出拆开的密钥、UTF-8 字符和常见 JSON 转义也会处理。
- 不要打印未经配置的新密钥、编码/变形后的凭据，或在镜像里烘焙凭据。脱敏不能识别任意未知秘密；任务运行期间不要更换凭据。
- 日志是操作者数据，不加入实验快照、不挂载到编码/知识库 Agent，也不回传到 Prompt。有、无知识库两侧保持相同任务、模型配置、预算、资源和评分输入。
- 新日志从头归档，不再自动删除超过 100 万字符的开头或超过 50 次执行的旧正文。日志会持续占用评测服务数据盘空间，请关注磁盘余量；本功能不自动删除历史记录。
- 实时模式初次取最近 6.4 万字符，后续增量读取，页面最多显示 20 万字符；完整模式分页读取所有已保存字符。两种模式共用同一归档。旧版本已经截断的开头、采集失败时丢失的内容无法补回，会明确提示。
- 新启动的直接受管 Agent/评分容器使用 Docker JSON 日志，不额外施加应用侧的轮转上限；保留 Docker daemon 的日志配置。容器启动后立即跟随输出；如果管理员配置了非常小的轮转窗口，或进程未刷新、采集被中断，不能保证补回未采集的输出。容器正常移除时 Docker 原始日志随之清理，脱敏归档保留。自定义命令的 `setup.log` / `agent.stderr.log` 文件仍各保留前约 8 MiB，超出后控制台继续输出并归档。官方评分器自行创建的子容器保持上游策略。
- 容器正常结束并自动移除后，归档仍能查看。评测服务重启会标记旧采集流已中断，不将其误报为任务失败。不会自动重新连接旧运行、重跑模型或追认旧日志。

升级自定义命令适配器或项目环境构建实现会改变相应冻结校验值。已准备实验继续受原有一致性检查保护；如提示实现已变化，应保留旧版本环境完成旧实验，或用新版重新准备新实验，不要改写历史快照绕过检查。

## 开发验证

常规回归：`npm test`、`npm run build`、`npm run worker:test`。纯 Node 脱敏测试：`node --test docker/agent-pi/console-stream.integration.mjs`。中英文页面验收：`node scripts/live-logs-ui-smoke.mjs`（需要 Playwright 和浏览器，可通过 `CTXBENCH_BROWSER_CHANNEL=msedge` 使用 Edge）。

`scripts/live-logs-container-smoke.py` 使用真正的 Docker 和 HTTP 接口，断言容器未结束时已能读取日志，覆盖自定义命令、知识库生成、Pi 求解、测试通过/失败、非零退出和超时。只用合成密钥与 mock Provider，不花模型额度。运行方式及挂载要求见脚本顶部；会构建并移除独立测试标签，不替换运行中的应用镜像。

2026-09-09 在 Ubuntu WSL Docker 实测 10 项通过：2 项模拟真实 Git 与 Docker 构建失败，核实 Agent 尚未启动时已经归档原始错误，构建日志可以跨 3 页读取；另外 8 项均在读取到首段输出后直接检查 Docker 容器仍为 `running`，不是只检查调用函数尚未返回。覆盖退出码 0、1、17、124；容器移除后仍能读取保留日志。合成凭据跨多次输出打印，页面接口、保存的控制台和日志数据库均未暴露原值。中英文页面另外验证了超过 120 万字符归档的逐页完整读取、较早日志来源和重试状态。此验收验证日志基础设施，不代表模型能力或知识库效果结论。
